# 待决问题

> 这些问题无法由代码/研究单独决定，需要业务/法务/产品裁决。每项给出推荐选项与影响；决定后转为 ADR 或更新需求。

## 1. Hisha 自身许可证

**问题**：IR/规范/SDK/本地运行时/云端如何许可？

**选项**：

- A（推荐）：Open Core——IR/schema/SDK/Local Runtime Apache-2.0；云端多租户/企业治理/市场商业许可。
- B：全部 Apache-2.0 + 托管收费；生态最大，但竞争对手可直接托管。
- C：AGPL/SSPL；保护托管收入，但阻碍企业嵌入/客户端分发，与 Publish Everywhere 冲突。
- D：双许可（社区 + 商业）；需 CLA/商标策略。

**建议**：A；先发布 IR/Skill/MCP 契约与 SDK，云端价值（治理/多租户/市场）商业授权。需法务设计 CLA/商标/贡献政策。

**影响**：Phase 5/6 发布、社区采用、融资/商业模式。

## 2. 商业模式与计费

**问题**：SaaS 如何收费（执行/节点/Token/席位/存储/市场分成）？

**建议**：Phase 6 前不定价；先计量（执行/节点/模型/存储/MCP 调用），保留 usage record。市场分成 Phase 6+ 再评估。

**影响**：数据模型/配额/计费/发票/税务；不在 Phase 1-4 实现。

## 3. 主要 GTM/目标客户

**问题**：先开发者/中小企业，还是大型企业/受监管行业？

**建议**：先开发者/自动化团队（Local + Workflow + Skills + MCP），再企业治理/私有化。理由：本地优先/低门槛是差异；企业销售周期长。

**影响**：Phase 1 UI/文档/定价/支持；企业需求（SSO/审计）可延后但架构预留。

## 4. Local Runtime 打包

**问题**：CLI + 本地 Web UI，还是 Electron/Tauri 桌面应用？

**建议**：Rust 单二进制 + 本地 Web UI（嵌入静态资源）；Phase 3+ 评估 Tauri 包装（不改变运行时）。理由：本地优先/单二进制/跨平台；桌面壳可后加。

**影响**：安装器/自动更新/系统托盘/文件关联。

## 5. Temporal 启用标准

**问题**：什么条件下把 `durable` 作为默认/推荐？

**建议**：PoC C 通过（恢复/审批/Worker 离线/多租户）且客户有长任务/强恢复需求；否则只用轻量运行时。Temporal 作为可选后端，不强制。

**影响**：Phase 3/6 运维/成本/部署。

## 6. Kestra/外部格式导入

**问题**：是否 Phase 1 支持 Kestra YAML/n8n JSON/BPMN 导入？

**建议**：Phase 1 只支持 Hisha YAML/JSON；Kestra 导入 Phase 5+ 按客户需求；BPMN 不导入（避免双模型）。理由：导入器维护高/语义丢失。

**影响**：迁移工具/市场/销售。

## 7. Agent Worker 语言（已决）

**问题**：Agent Worker 用 LangGraph JS 还是 Python？（已决：Python）

**决定**：Python 3.13 + LangGraph 作为可选 AI Worker（ADR-0004）；TS 只做 Agent Designer/管理；Rust 通过 gRPC 调用。理由：AI 生态/技术栈约束/可选性；Python 不是核心依赖。

**影响**：AI Worker 镜像/uv lock/可选部署；无 Python 时 Agent 禁用。

## 8. 多 Agent 默认策略

**问题**：是否默认启用 Supervisor/多 Agent？

**建议**：默认关闭；按 Agent 配置显式启用；预算/深度限制。理由：成本/可靠性/调试复杂度。

**影响**：Agent Designer/预算/评估。

## 9. 合规范围

**问题**：SOC2/ISO 27001/数据驻留/行业合规（金融/医疗）？

**建议**：Phase 6 前确定目标；先做审计/加密/保留/备份基础；合规认证按客户需求。不要声称已合规。

**影响**：基础设施/流程/成本/销售。

## 10. Windows/macOS 沙箱

**问题**：是否强制容器运行不可信 Skill？

**建议**：默认受限进程 + 风险提示；高风险/不可信默认容器；企业可强制“仅容器”。理由：本地无容器体验/兼容性；安全优先。

**影响**：Local Runtime 安装/依赖/支持。

## 11. 市场审核/运营

**问题**：谁审核插件/Skill？人工成本/责任？

**建议**：Phase 5 先自动扫描 + 小团队人工审核高风险；官方/验证发布者优先；建立举报/下架流程。市场分成 Phase 6+。

**影响**：市场 launch/法务/运营。

## 12. 遥测/分析

**问题**：是否收集产品遥测？默认开/关？

**建议**：默认关闭/显式 opt-in；本地优先；只收集匿名性能/错误；不收集 Workflow 内容/secret。理由：隐私/企业信任。

**影响**：产品分析/隐私政策。

## 13. 移动端/窄屏支持级别

**问题**：是否做原生移动 App？

**建议**：不做原生；Web 窄屏（607px）支持查看/审批/运行监控；Designer 桌面优先。理由：画布编辑在移动端体验差；审批/监控可移动。

**影响**：UI 范围/测试。

## 14. 默认模型策略

**问题**：默认接哪个模型/是否提供本地模型？

**建议**：不绑定单一 provider；LiteLLM 接入；本地模型可选（Ollama/llama.cpp）；无模型模式必须可用。默认模型由部署配置，不给“平台内置模型”。

**影响**：成本/隐私/体验。

## 15. 文档/UI 语言优先级

**问题**：文档中文、UI 日语默认已定；是否额外维护英文文档？

**建议**：Phase 1 中文设计文档 + UI 三语；对外开源前补英文核心文档（IR/Skill/MCP/安全）。理由：日本市场优先/开源生态需要英文。

**影响**：文档工作量/社区。
