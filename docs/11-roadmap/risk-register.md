## 2. 高风险优先处理

1. **R-01/R-02 许可**：在任何代码引入前完成许可证门禁与法务复核；n8n/Dify/EE/专有 Skill 禁止进入仓库。
2. **R-03/R-04 IR/往返**：PoC A 是 Phase 1 前置；不通过不进入实现。
3. **R-05/R-06 执行**：先轻量运行时，Temporal 仅 PoC；不承诺未验证的 durable 语义。
4. **R-09/R-10 安全**：沙箱/租户隔离测试是发布门禁。
5. **R-11/R-13 MCP/客户端**：PoC B 用真实客户端验证；不假设一个配置适配所有。
6. **R-17 范围**：Phase 1 只做 M0；其余延后。

## 4. 评审节奏

- 每个 Phase 开始/结束更新风险表。
- 高风险触发时暂停相关发布，做根因/缓解。
- 新依赖/新协议/新客户端接入必须评估 R-01/R-02/R-11/R-13。
- 风险关闭需证据（测试/审计/法务意见）。
